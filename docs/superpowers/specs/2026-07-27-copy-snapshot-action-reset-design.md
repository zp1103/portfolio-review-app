# 复制快照动作重置设计

## 背景

“复制为新快照”会把上一期持仓作为新一周的录入草稿。当前实现已经把复制草稿中的交易金额重置为 `0`，但仍继承上一期的动作字段，导致没有本周交易的持仓继续显示为“买入”“卖出”或“调仓”，容易在回看交易历史时产生误判。

根因位于 `app/main.py` 的 `_build_form_values()`：`copy_as_new=True` 时，`transaction_amount` 被重置，而 `action` 仍直接使用原持仓值。

## 决策

仅在构建“复制为新快照”的表单预填数据时，将每条持仓的动作统一重置为 `hold`。

复制草稿中的相关字段规则如下：

- `action`：统一设为 `hold`。
- `transaction_amount`：继续按现有逻辑设为 `0`。
- `weekly_pnl_amount`：继续按现有逻辑设为 `0`。
- `previous_amount` 和 `previous_cumulative_pnl_amount`：继续保留上一期数据，用于推导本周盈亏。

## 作用范围

本次修改只影响通过 `/?copy_id=<snapshot_id>` 打开的复制草稿。

以下行为保持不变：

- 原快照及其持仓动作不会被修改。
- 编辑现有快照时继续显示原动作。
- 普通新增快照的默认动作仍为 `hold`。
- HTML 表单保存时不额外修正用户选择的动作。
- JSON API 创建快照时不额外修正传入动作。
- 数据库中已有的历史记录不做迁移或批量修正。

## 数据流

1. 用户点击“复制为新快照”。
2. Dashboard 通过 `copy_id` 读取原快照。
3. `_build_form_values(snapshot, copy_as_new=True)` 构建新一周草稿。
4. 每条持仓保留资产、分类、金额和累计收益等基础数据，但动作设为 `hold`，交易金额设为 `0`。
5. 用户可以在提交前按本周实际操作重新选择动作、录入交易金额。

## 实现位置

在 `app/main.py` 的 `_build_form_values()` 中，把持仓字典的 `action` 改为：

- 复制草稿：`hold`
- 非复制场景：原持仓动作

不在模板、数据库或服务层增加额外归一化逻辑，以确保修改范围严格限制在复制草稿。

## 测试设计

扩展 API 页面测试，创建一个包含 `buy`、`sell` 和 `rebalance` 三种动作的原快照，然后访问复制页面并验证：

- 三条持仓在复制草稿中均选中 `hold`。
- 三条持仓的交易金额均为 `0`。
- 原快照中的动作仍分别为 `buy`、`sell` 和 `rebalance`。

同时保留或补充编辑页面断言，确认编辑原快照时不会把动作重置为 `hold`。

## 验收标准

- 复制任意历史快照后，所有持仓动作默认显示为“持有”。
- 复制草稿的交易金额为 `0`。
- 用户仍能在提交前手工选择本周真实动作。
- 原快照、编辑流程、普通新增和 JSON API 行为不发生变化。
- 相关回归测试和完整测试套件通过。
